# Owner-invoked checkpoint-intent host

Candidate policy and implementation for review; not authorization to execute a
live transaction from the hourly automation. This implements the bounded PR358
proposal using the existing mandatory-gated execute_supervised function. No new
CLI, provider, credentials, scheduler, store or service is added. The binary
versioned-custody path is unchanged. AGENTS rule 11 is the explicit proposed
ordinary-processing exception; rule 10 append restrictions remain unchanged.

Call `execute_checkpoint_supervised(context=..., supervised_kwargs=...,
initialize=False, read_checkpoint=..., write_checkpoint=...,
verify_assignment=...)`. The native argument dict has exactly journal_path,
prepared, source_page, source_sha256, output_name, analysis, expected_owner,
request, allow_create, analysis_gate. No update or legacy options are accepted.

Context has exactly transaction_id, assignment_id, actor, source_revision,
code_revision, policy_revision and destination. Destination has parent (name or
null) and dependencies (list). Preserve the stable context across reconciliation;
do not allocate a fresh transaction to escape uncertainty. The native output
binding includes source chunks locally; the remote intent retains the source
receipt, exact revision, desired output, full analysis gate and native-binding
digest, without copying original chunks from Notion.

## Trusted host callback requirements

- read_checkpoint(transaction_id) freshly returns the exact retained envelope or
  None for independently confirmed absence. It must select one authoritative
  private checkpoint; a failed/missing-access search is never absence.
- write_checkpoint(transaction_id, envelope) persists this transaction without
  overwriting unrelated checkpoint content. Preserve prior intent/history. A
  lost acknowledgment is uncertain; this wrapper never retries it blindly.
- verify_assignment(expected) freshly returns exactly expected only after the
  host independently establishes current exclusive task assignment for the
  owner-invoked session: mode=OWNER_INVOKED_SUPERVISED, transaction_id,
  assignment_id, actor. Otherwise raise or return a nonmatch. An hourly prompt,
  context field, callback that echoes its argument, or matching checkpoint reads
  is NOT assignment evidence. Recheck at entry, retention and dispatch. Native
  flock serializes only cooperating local callers, not external writers.
- request retains the existing authenticated archive_read/cortex_get/cortex_create
  contract. Independently bind the actual current source revision and complete
  source acquisition to context.source_revision on EVERY source read. Validate
  actual account, parent, dependencies and target-specific grants against the
  context, rather than treating its labels as evidence. Source output originals
  remain unchanged. A create payload is not permission or destination selection.

These are host authority obligations, not authenticated facts generated by Python.
The wrapper freezes context/gate and rejects source/output gate mismatches before
callbacks. A companion .checkpoint.lock spans this operation; the native host
still holds its own journal lock and commits FULL-synchronous INTENT. At the
mutation callback the wrapper checks actual local INTENT, persists the exact
remote intent, independently reads it, rechecks source and destination, verifies
assignment again and dispatches at most once. No conditional remote overwrite or
CAS is claimed; exclusive assignment is necessary for this bounded exception.

After native source/output readback, save the actual execution receipt and read it
back, then freshly reconcile the source/output again read-only. Only that matched
milestone returns SUPERVISED_RECEIPT_READBACK_MATCHED and transaction_complete=true.
That field refers to this bounded source/output/receipt delivery, not independent
factual verification, all Nexus routing dimensions, unattended operation or audit
promotion. Required routing/connection work must already be assessed in the gate.
Pending required actions cannot be declared complete merely because storage works.

Unknown write or mismatching binding/assignment/source/output stops or returns
HOLD. Native INTENT prevents a second create on re-entry, including when the
provider committed but its reply was lost. An exact existing output without prior
retained intent is not adopted as fresh processing. A lost local journal with
retained intent/receipt is always HOLD, including initialize=True. No snapshot
restoration or journal reconstruction is installed. Do not use a different path,
ID or checkpoint mapping to bypass the hold. An uncertain remote intent cannot
be cleared merely because the output is absent.

## Single-host assignment guard

A trusted host can hold `hold_supervised_assignment` from
`nexus_sandbox.supervised_assignment` around the entire
`execute_checkpoint_supervised` call and pass the yielded verifier as
`verify_assignment`. Use one private host-owned lock directory for every
cooperating writer and the provider's exact owner ID and canonical output name.
A second local writer for that destination fails immediately, even if it uses a
different transaction ID or journal.

The host's independent assignment reader must freshly return the exact
`owner`, `output_name`, `mode`, `transaction_id`, `assignment_id` and
`actor` fields from owner-controlled assignment state. The guard compares
that state at each existing verification point while holding the lock. Reject
missing, revoked or mismatched state. Keep the same lock directory and do not
replace its lock files during use.

Use this only when the host controls every eligible writer for the destination
and they use the same directory and guard. A reservation in an hourly prompt
does not establish that boundary. This is local exclusion; it does not fence
external writers or install a live assignment reader or Chat dispatcher.

## Validation and rollback

`PYTHONPATH=src python3 -m unittest discover -s tests/unit -p
test_checkpoint_supervised_host.py -v` exercises synthetic callbacks and actual
SQLite journals, not real account grants or exclusive assignment. Cases cover
create/replay, scheduled assignment, invalid gate, failed/lost intent writes,
source changes, assignment revocation, uncertain provider effects, lost local
journal and append exclusion. Full validation uses tools/validate.py.

Rollback removes the optional module/tests/document and proposed AGENTS rule 11.
Retain all real journals, remote intent/receipts and task mappings. No current
workflow, schedule, existing entrypoint or active provider output is changed.
