# Bounded GitHub test-log decoding

The deferred maintenance bridge could bind GitHub run-attempt/job metadata but could not parse the provider's timestamped logs. tools/github_ci_logs.py adds an explicit parser for one complete verbose unittest suite inside a GitHub text job log. Use retrieve(..., read_job_log=reader, case_parser=extract_github_cases). The existing plain parser remains the default.

The decoder enforces the existing 2 MiB UTF-8 input bound, requires a UTC timestamp on each nonempty line, accepts one leading BOM and CRLF line endings, and removes only ANSI SGR colors. Other control sequences hold with no cases. The underlying parser requires one complete matching case count and summary, unique canonical IDs and diagnostic sections for failures. Diagnostics are hashed; raw logs are neither executed nor included in returned findings. Method-qualified identifiers observed in newer Python unittest output are no longer duplicated. Multiple suites, truncated or unrecognized output and JSON synthetic-run reports hold as incomplete evidence.

Live readback used the connected GitHub tool to retrieve completed run 40247091859, attempt 1, job 121330844546 on source bd8e016c4824ace740546373929b50a2462e8469. The original timestamped text and original exact-attempt metadata/jobs responses were passed through the bridge offline: 13 canonical passing cases, complete bound job/case evidence, HEALTHY, zero findings. No failing live run was diagnosed. Sanitized evidence, log hash and case IDs are in github-ci-log-readback.json; raw logs and transport credentials are not committed.

Local validation: 265 tests pass, including seven new decoder regression methods covering real observed timestamp/BOM and method-ID formats, backward compatibility, colors/CRLF, malformed and oversized data, duplicate/truncated/unsupported suites, synthetic failure hashes and exact job binding. Hosted validation is required for the committed revision. Authentication, bounded network retrieval and complete-response delivery remain host responsibilities. No scheduler, token loading, workflow change, autonomous repair or audit-gate promotion is installed.
