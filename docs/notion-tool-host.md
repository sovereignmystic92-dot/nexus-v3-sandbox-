# Tool-mediated audit receipt and journal custody — review proposal

This adds an executable JSON-line host handoff to PR86; it is not an installed
ChatGPT interceptor or background listener. `notion_tool_handoff.run` accepts
only the canonical Foundation Audit destination and one additive, operation-bound
`NXS_TOOL_HANDOFF_RECEIPT_V1` receipt. It cannot create transcript source pages,
replace their text, change settings or call Cortex.

The trusted surrounding host services six bounded methods using its existing
Notion MCP capability: confirm_new_enrollment, observe_reviews,
notion_read_receipt, notion_append_receipt, journal_publish and journal_fetch.
The runner does not inspect credentials or make HTTP requests. The host must
independently check exact destination/source, current authority, native gates,
full receipt inventory, actual reviewer snapshots and their independent digest
anchors. `complete=true` is a host attestation, not proof generated by this code.
The receipt projection is lossless for this one enrolled event; it is not a
general Notion-page or transcript parser.

The mutation uses the existing ApprovedWriteBoundary. After its SQLite
DISPATCHING commit, JournalCustody serializes the existing journal, bounds it to
96 KiB and verifies external publication by fetching the exact envelope. Only
then are context/reviews reobserved and the Notion mutation callback invoked.
After successful content readback, the VERIFIED journal is likewise published
and fetched before durable completion is returned. Publication/readback failure
holds; it never makes the mutation eligible for blind replay.

Custody envelopes bind request ID, full review context, serialized SQLite digest
and bytes. They contain no credentials or transcript body. Host publication must
attach the complete envelope durably under the audit and return its exact record
ID; an unplaced temporary upload does not count. After process/local loss, use
explicit restore mode with the separately retained saved record ID/digest and
current expected context. Restore validates hashes, schema, integrity and row
binding and exclusively creates a new local journal. It never overwrites one or
falls back to a fresh operation on missing/invalid custody. DISPATCHING may be
the latest durable state after a lost reply; exact target readback reconciles it
without a second mutation. Missing target still holds.

This extends process-restart recovery to externally held journal snapshots when
the host actually supplies and verifies that custody. Synthetic tests do not
establish Notion durability, later scheduled continuity, provider fencing,
cross-worker safety or complete host-loss recovery. Existing single-worker/CP09
pause and production restrictions remain. Snapshot replacement and independent
writers are outside this trust model. Snapshots themselves do not authenticate
reviewer statements or external facts.

Validation: 33 distinct focused tests (23 earlier plus 10 new custody/host cases)
passed locally, including a separate Python process that restores a saved
DISPATCHING journal and reconciles an already-applied target without invoking
the mutation callback. Wrong/missing custody, enrollment, context drift during
custody, incomplete receipt reads, and result-custody failure are covered.
All host/provider/custody callbacks in these tests are synthetic. No live
connector execution is inferred.

Coherence disposition REFINE: retain the existing SQLite journal and write
boundary, adding verified external custody and a narrow tool handoff. No parallel
pipeline or journal state machine. Security-control review and applicable native
gates precede adoption/activation. A single live audit-receipt test is the next
bounded activation proposal; the Haiti transcript is not recreated or replayed.
