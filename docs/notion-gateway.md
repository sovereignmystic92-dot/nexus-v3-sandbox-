# Fixed-origin Notion HTTPS gateway — not activated

`NotionGateway` implements the request callback used by `NotionRESTTransport`. It uses the Python standard library, has no automatic environment lookup, and receives a credential-provider callback only from its explicit caller. `enabled=False` is the default. Import, construction and disabled calls do not request credentials or open sockets. No real credential or direct Notion API request has been used to validate this code.

## Implemented controls

- HTTPS host fixed to api.notion.com, port 443, path prefix /v1; default verified TLS context. Absolute URLs, unexpected headers, other methods and other endpoint families are rejected before credential lookup. No redirects are followed.
- Read the configured root, discover child IDs only from its block enumeration or a successful create acknowledgment, validate each child's direct parent through metadata before permitting its body read, and invalidate old body grants when metadata is refreshed. These checks do not establish server-side credential restrictions or solve concurrent page moves.
- Permit POST /pages only for the same canonical synthetic body generated by the transport, bound to the configured parent. Extra properties, altered content, wrong hashes and other destinations are denied. No update/delete endpoint is exposed.
- At most 200 requests in one 120-second session. Each socket operation has a 10-second timeout. Response chunks are checked against the session deadline between reads; an in-progress socket operation can overrun the session deadline by its timeout. Decoded response input is limited to 1 MiB; request bodies to 512,000 bytes. This is a bounded session, not a hard real-time cancellation guarantee.
- No automatic retries for POST, GET, redirect, rate limit, server failure or timeout. Uncertain create outcomes are handled by the durable receipt engine's reconciliation policy.
- Credentials are requested only after scope validation and explicit enablement. They are passed in the Authorization header, not URLs, source files, logs or evidence. Gateway errors omit response bodies, headers and injected exception text. Its repr omits the credential provider. The caller/provider still controls how the secret is stored and must itself be trusted.

The injectable HTTPS factory is exclusively a trusted testing seam. Production callers must use the default verified HTTPSConnection implementation and a private secret provider. The gateway does not automatically establish the credential's actual content permissions. The owner must provision a dedicated connection restricted to the synthetic root before live enablement.
